# V0.2 provider work log

## Initial inspection

- `SwitchboardApplication` manually wired sherpa-onnx, the wake coordinator, one fixed mock provider, the action router, and Android TTS.
- `DefaultWakeWordProvider` already converged real/simulated detections, stopped `AudioRecord` for assistant work, rejected duplicate states, retried recoverable errors, and rearmed after the controller returned.
- `AssistantController` accepted typed text but wake events sent an internal mock sentinel; provider selection was not dynamic.
- `SwitchboardRecognitionService` was a role-registration placeholder and returned `ERROR_CLIENT`; no post-wake dictation engine was invoked by the app process.
- `VoiceProvider.speak` already suspended on `UtteranceProgressListener`, providing the necessary TTS completion boundary.
- Compose exposed a read-only mock provider field and mapped both waiting and active assistant phases to a broad Active diagnostic.
- The foreground notification rendered wake state only. Stop released wake and TTS but did not explicitly cancel a network request because none existed.
- The manifest had microphone/foreground/notification permissions and deliberately lacked `INTERNET`.

## Adaptation

- Preserved the sherpa detector, local model assets, wake coordinator, developer simulation path, assistant-role services, action router, visual structure, and mock provider.
- Added a backend-held credential boundary and a TypeScript Cloudflare Worker.
- Added `OpenAiBackendProvider` behind the existing provider/session contracts.
- Added one-shot Android speech recognition behind a new `SpeechInputEngine` contract.
- Converged typed and spoken transcripts on one coordinator message function.
- Replaced broad Active state with Idle, Listening, Thinking, Speaking, and Error.
- Added bounded in-memory conversation context, cancellation, provider switching, safe errors, diagnostics, and state-aware notification text.

- Baseline Android unit tests passed before implementation.
- Worker type generation, strict TypeScript checking, and six Worker runtime tests pass.
- Local `GET /health` returned HTTP 200 with `{ "ok": true }`.
- One controlled live assistant request reached the Worker/OpenAI boundary and returned a safely mapped HTTP 429. No retry was made; usable Platform request capacity remains required for a generated response.
- Final Android unit, lint, assemble, manifest, and artifact checks are recorded in the final task report.
